# Positron v0.3.0

> **Status:** release candidate, pending publication

Positron v0.3.0 adds installed supervised onboarding. The public installer
remains the consumer entry point; the safe demo remains the default and
supervised Real Mode requires explicit configuration and invocation.

## Installed supervised onboarding

The installed launcher supports `positron configure supervised`,
`positron doctor --supervised`, `positron start --supervised`,
`positron status --supervised`, and `positron stop --supervised`.

Configuration uses the versioned `positron.supervised-config.v1` contract in
the user-owned XDG configuration directory. Repository coordinates, tool
discovery, provider/model selection, and prerequisite validation are handled
through the launcher without requiring a Positron clone, `.env` editing, or
manual Compose invocation.

## Explicit profile separation

`positron start` remains the safe fake/demo profile. The supervised profile is
explicitly selected with `--supervised`, uses its own Docker project identity,
and never starts a task merely because the runtime starts.

## Existing architecture reused

Supervised startup delegates to the existing advanced `docker-compose.yml`,
server, worker, durable control plane, readiness contract, and real adapters.
No second runtime, control plane, database, or adapter implementation was
introduced.

## Security boundaries

- Configuration and secret directories are user-owned and protected.
- GitHub tokens are accepted from a protected source or hidden prompt, never
  as a normal command argument, and are not displayed by the launcher.
- Push is an explicit opt-in and is scoped to the configured repository.
- Merge remains disabled and the merge kill switch remains active.
- Unsupervised Real Mode remains disabled.
- No npm/container publication, deployment, or production repository mutation
  is part of this release.

## Qualification

This release candidate is qualified through the product and release gates
recorded in Issue [#493](https://github.com/Mueller-Systems-Lab/Positron/issues/493).
Publication and post-publication installed real Issue-to-PR acceptance are
required before this document is treated as a stable release record.

## Known limitations

Real supervised execution still requires an already-authorized, least-privilege
GitHub credential and a configured zero-cost or local OpenCode provider/model.
Unsupervised productive Real Mode remains intentionally unavailable.
